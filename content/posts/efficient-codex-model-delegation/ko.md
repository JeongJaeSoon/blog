메인 에이전트는 어려운 판단, 작업 분할, 결과 통합에 집중합니다. 독립적으로 진행할 수
있는 작업은 서브에이전트에 맡길 수 있지만, 그렇다고 모든 하위 작업을 위임해야 한다는
뜻은 아닙니다. 작업을 설명하고 필요한 문맥을 전달하고 돌아온 결과를 검토하는 비용보다
절감 효과가 클 때만 위임합니다.

이 차이는 중요합니다. 짧고 긴밀하게 연결된 작업을 나누면 대기 시간과 토큰만 늘고,
사고의 흐름도 끊길 수 있습니다. 위임은 기본 워크플로가 아니라, 품질 기준을 해치지
않으면서 전체 시간과 비용을 줄일 수 있을 때 쓰는 최적화입니다.

## 먼저 위임할지 판단하기

다음과 같은 작업은 보통 메인 에이전트가 직접 처리하는 편이 낫습니다.

- 한두 번의 빠른 확인이나 작은 수정으로 끝나는 작업
- 실제로 처리하는 것보다 설명하는 데 더 많은 노력이 드는 작업
- 다음 판단을 위해 결과를 즉시 써야 하는 작업
- 분리해서 아끼는 비용보다 검토 비용이 더 큰 작업

반대로 메인 작업과 독립적으로 진행할 수 있고, 범위가 명확하면서 충분히 크며, 병렬
실행의 이점이 있는 작업은 위임하기 좋습니다. 범위가 분명한 조사, 검토, 구현이 여기에
해당합니다. 판단이 애매하면 메인 에이전트가 그대로 처리합니다.

## 난이도에 맞춰 서브에이전트 모델 고르기

위임하기로 결정했다면 작업 난이도에 따라 모델을 고릅니다.

| 작업 난이도 | 서브에이전트 모델 | 적합한 작업 |
| --- | --- | --- |
| 단순 | `gpt-5.6-luna` | 범위가 정해진 확인, 짧은 요약, 단순한 수정 |
| 일반 | `gpt-5.6-terra` | 독립적으로 끝낼 수 있는 조사나 구현 |
| 복잡 | `gpt-5.6-sol` | 여러 조건을 검토해야 하는 분석이나 설계 |

운영 규칙상 서브에이전트에는 Astra를 사용하지 않습니다. 메인 모델은 깊은 판단과 통합에
집중하고, 분리해도 품질을 유지할 수 있는 작업에는 필요한 수준을 충족하는 가장 비용
효율적인 모델을 배정합니다.

## 확인된 내용과 아직 확인되지 않은 내용

2026년 9월 11일 기준으로 로컬 설정에서 메인 모델은 `gpt-6-astra`, 추론 강도는 `high`,
기본 서브에이전트 모델은 `gpt-5.6-terra`임을 확인했습니다. 위임 정책에도 단순·일반·
복잡 작업에 각각 Luna·Terra·Sol을 명시적으로 선택한다는 규칙이 기록돼 있습니다.

실행 기록에서는 Astra로 실행된 메인 작업과 Luna를 명시적으로 지정한 서브에이전트
작업을 확인했습니다. CLI 0.153.4에서 분리한 검증으로 Terra 기본값도 읽어 왔습니다.

다만 이 확인만으로 모든 작업이 자동 분류되거나 자동 위임된다고 말할 수는 없습니다.
관찰한 서브에이전트 실행에서는 Luna를 명시했으므로, 모델을 생략했을 때 Terra가
선택되는지는 검증하지 않았습니다. 이 정책은 강제 라우팅 장치가 아니라 에이전트가
따르는 행동 지침입니다. 설정 전체에 대한 엄격한 검증도 모델과 관계없는 지원되지 않는
항목 때문에 끝까지 완료되지 않았습니다.

토큰 수, 비용, 계정 사용량이 실제로 줄었는지도 아직 측정하지 않았습니다. 위임에는
언제나 문맥 전달과 결과 검토 비용이 따르므로, 전체 사용량이 반드시 줄어드는 것은
아닙니다. 이 규칙은 더 좁게 적용합니다. 그 비용을 충분히 되돌려 받을 가능성이 있는
작업만 위임합니다.
