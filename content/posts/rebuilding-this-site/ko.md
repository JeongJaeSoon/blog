예전 사이트에는 구매한 포트폴리오 테마를 거의 그대로 쓰고 있었습니다. 겉보기에는
괜찮았지만, 페이지마다 Bootstrap, Font Awesome, Isotope, Magnific Popup, smooth-scrollbar,
anime.js와 슬라이더 라이브러리까지 따라왔습니다. 콘텐츠를 읽는 `fs.readdirSync` 코드 마흔
줄도 분류별로 여덟 번 복사되어 있었습니다.

심지어 데모 작성자 이름도 Artur Carter 그대로였습니다. 내 사이트라고 하기 어려웠습니다.

## 지금의 구성

- App Router와 정적 렌더링을 사용하는 **Next.js 16**
- **React 19**와 **TypeScript**
- JavaScript 설정 파일 대신 CSS에서 설정하는 **Tailwind CSS v4**
- 문법 강조에 **Shiki**를 쓰는 **unified / remark / rehype**

UI 프레임워크와 컴포넌트 라이브러리, 기성 테마를 모두 뺐습니다. 의존성 목록이 한 화면에
들어올 만큼 짧아졌고, 그게 다시 만든 가장 분명한 이유입니다.

## 콘텐츠가 있는 곳

볼 곳은 세 군데뿐입니다.

```text
content/profile.ts      → 사실: 날짜, URL, 저장소, 기술 스택
content/i18n/{en,ko,ja} → 번역할 모든 문자열
content/posts/<slug>/{en,ko,ja}.md → 블로그
```

핵심은 앞의 둘을 나눈 것입니다. 입사일, 저장소 이름, 프로젝트 언어 같은 사실 데이터는
**한 번만** 저장하고 문장만 번역합니다. `2023-11`을 세 군데에 적으면 언젠가는 한 군데를
빼먹게 됩니다.

두 부분 모두 타입으로 관리하므로, 날짜가 빠진 역할을 추가하거나 키가 빠진 로케일을
추가하면 빈 span을 렌더링하는 대신 빌드가 실패합니다. 게시물은 frontmatter가 있는 Markdown
파일입니다.

```yaml
---
title: A post
date: '2026-08-30'
summary: One or two sentences.
tags: [nextjs]
lang: en
draft: true
---
```

블로그는 글 하나에 폴더 하나를 씁니다. 폴더 안에는 영어·한국어·일본어 Markdown을 두고,
폴더 이름을 공통 URL 슬러그로 사용합니다. `lang`이 파일명과 다르거나 번역 하나가 빠지면
빌드를 멈춥니다. 언어 버튼을 눌렀는데 404가 나오는 것보다는 낫습니다.

`draft: true`로 설정하면 게시물은 `next dev`에서는 보이지만, 빌드와 RSS 피드, 사이트맵에서는
제외됩니다.

## 이력서인 부분

홈페이지 자체가 이력서입니다. 같은 타입 데이터에서 읽어 와 깔끔하게 인쇄합니다. `Cmd+P`를
누르면 내비게이션, 푸터, “모든 저장소” 링크를 빼고 연락처 핸들을 펼치므로, 종이 버전에도
연락처가 남습니다. 하나의 진실 공급원, 두 종류의 독자, 세 가지 언어입니다.

## 번역이 내 데이터 모델에 가르쳐 준 것

회사 이름은 사실 데이터라고 생각했습니다. 그런데 `freee K.K.`, `freee株式会社`,
`freee 주식회사`는 같은 회사여도 표시 언어에 따라 이름이 달라집니다. 일본어 페이지에는
그중 두 이름이 위아래로 함께 나오기도 했습니다.

출신지를 표시하는 줄은 더 분명했습니다. `{location} — from {origin}`이라는 조합 자체가
영어 어순입니다. 한국어는 `대구 출신`, 일본어는 `韓国・大邱出身`처럼 ‘출신’이 뒤에 옵니다.
따로 작업한 두 번역자가 모두 문장을 코드에 억지로 맞추고 있었습니다. 두 사람이 같은 곳에서
막힌다면 번역이 아니라 데이터 모델을 고칠 차례입니다.
