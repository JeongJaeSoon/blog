이 사이트는 예전에 구매한 포트폴리오 테마로 돌아갔습니다. 보기에는 괜찮았지만, 모든
페이지가 Bootstrap, Font Awesome, Isotope, Magnific Popup, smooth-scrollbar, anime.js, 슬라이더
라이브러리까지 끌고 다녔습니다. 콘텐츠 로더도 분류마다 하나씩, `fs.readdirSync`를 쓰는 같은
마흔 줄이 여덟 번 복사되어 있었습니다.

내 것은 아무것도 없었습니다. 데모 작성자 이름도 여전히 Artur Carter였습니다.

## 지금의 구성

- App Router와 정적 렌더링을 사용하는 **Next.js 16**
- **React 19**와 **TypeScript**
- JavaScript 설정 파일 대신 CSS에서 설정하는 **Tailwind CSS v4**
- 문법 강조에 **Shiki**를 쓰는 **unified / remark / rehype**

UI 프레임워크도, 컴포넌트 라이브러리도, 테마도 없습니다. 의존성 목록이 한 화면에서
읽힐 만큼 짧다는 점이 핵심입니다.

## 콘텐츠가 있는 곳

세 곳뿐입니다. 이것이 전체 구조를 이해하는 방식입니다.

```text
content/profile.ts      → 사실: 날짜, URL, 저장소, 기술 스택
content/i18n/{en,ko,ja} → 번역할 모든 문자열
content/posts/<slug>/{en,ko,ja}.md → 블로그
```

앞의 둘을 나눈 부분이 설명할 가치가 있습니다. 입사일, 저장소 이름, 프로젝트에 쓰인
언어처럼 사실인 정보는 **한 번만** 저장합니다. 번역하는 것은 문장뿐입니다. `2023-11`을
세 번 저장하면 세 사본은 조용히 서로 달라지기 시작합니다.

두 부분 모두 타입으로 관리하므로, 날짜가 빠진 역할을 추가하거나 키가 빠진 로케일을
추가하면 빈 span을 렌더링하는 대신 빌드가 실패합니다. 게시물은 frontmatter가 있는 Markdown
파일입니다.

```yaml
---
title: A post
date: '2026-08-30'
summary: One or two sentences.
tags: [nextjs]
lang: en
draft: true
---
```

폴더 하나가 글 하나를 나타내며, 폴더 안의 Markdown 세 개가 영어·한국어·일본어 번역본입니다.
폴더 이름은 세 번역본이 공유하는 URL 슬러그이고, `lang`은 파일명과 일치해야 합니다. 번역본이
하나라도 빠지면 빌드를 실패시켜 언어 전환이 404로 연결되지 않게 합니다.

`draft: true`로 설정하면 게시물은 `next dev`에서는 보이지만, 빌드와 RSS 피드, 사이트맵에서는
제외됩니다.

## 이력서인 부분

홈페이지 자체가 이력서입니다. 같은 타입 데이터에서 읽어 와 깔끔하게 인쇄합니다. `Cmd+P`를
누르면 내비게이션, 푸터, “모든 저장소” 링크를 빼고 연락처 핸들을 펼치므로, 종이 버전에도
연락처가 남습니다. 하나의 진실 공급원, 두 종류의 독자, 세 가지 언어입니다.

## 번역이 내 데이터 모델에 가르쳐 준 것

회사 이름은 사실이라고 생각했습니다. 그렇지 않았습니다. `freee K.K.`, `freee株式会社`,
`freee 주식회사`는 같은 회사이고, 일본어 페이지에서는 그중 하나가 다른 하나 바로 위에
그대로 표시되고 있었습니다.

위치 줄은 같은 점을 더 크게 보여 주었습니다. 나는 이를 `{location} — from {origin}`으로
만들었는데, 여기에 영어 어순이 조용히 들어가 있습니다. 한국어는 표지를 마지막에 둡니다
(`대구 출신`). 일본어도 그렇습니다(`韓国・大邱出身`). 독립적으로 작업한 두 번역자는 모두
코드를 바꾸기보다 표현을 그 구조에 맞추고 있었습니다. 서로 다른 방향에서 온 두 사람이
같은 벽에 부딪힌다면, 그 벽이 버그입니다.
