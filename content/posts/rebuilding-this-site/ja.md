このサイトは以前、購入したポートフォリオテーマで動いていました。見た目は悪くなかった
ものの、各ページに Bootstrap、Font Awesome、Isotope、Magnific Popup、smooth-scrollbar、
anime.js、スライダーライブラリまで読み込まれていました。コンテンツローダーも、
`fs.readdirSync` を使う同じ四十行が分類ごとに八回コピーされていました。

自分のものは何もありませんでした。デモの作者名は Artur Carter のままでした。

## 現在の構成

- App Router と静的レンダリングを使う **Next.js 16**
- **React 19** と **TypeScript**
- JavaScript の設定ファイルではなく CSS で設定した **Tailwind CSS v4**
- シンタックスハイライトに **Shiki** を使う **unified / remark / rehype**

UIフレームワークも、コンポーネントライブラリも、テーマもありません。依存関係の一覧が
一画面で読めるくらい短いことがポイントです。

## コンテンツの置き場所

置き場所は三つだけで、それが全体の考え方です。

```text
content/profile.ts      → 事実: 日付、URL、リポジトリ、技術スタック
content/i18n/{en,ko,ja} → 翻訳が必要なすべての文字列
content/posts/<slug>/{en,ko,ja}.md → ブログ
```

説明すべきなのは、最初の二つを分けたことです。入社日、リポジトリ名、プロジェクトで
使う言語のような事実は **一度だけ** 保存します。翻訳するのは文章だけです。`2023-11` を
三回保存すると、三つのコピーが気づかないうちにずれていきます。

両方とも型付けされているので、開始日がない職歴やキーが欠けたロケールを追加すると、
空の span を描画するのではなくビルドが失敗します。投稿は frontmatter を持つ Markdown
ファイルです。

```yaml
---
title: A post
date: '2026-08-30'
summary: One or two sentences.
tags: [nextjs]
lang: en
draft: true
---
```

一つのディレクトリが一つの記事を表し、その中の三つの Markdown ファイルが英語、韓国語、
日本語版になります。ディレクトリ名は共通の URL スラッグで、`lang` はファイル名と一致
させます。翻訳が一つでも欠けていればビルドを失敗させ、言語切替が 404 に向かうのを防ぎます。

`draft: true` にすると、投稿は `next dev` では見えますが、ビルド、RSSフィード、サイトマップ
からは除外されます。

## 履歴書としての部分

ホームページ自体が履歴書です。同じ型付きデータを読み、きれいに印刷されます。`Cmd+P` を
押すとナビゲーション、フッター、「すべてのリポジトリ」へのリンクを外し、連絡先の
ハンドルを展開するので、紙の版にも連絡先が残ります。一つの情報源、二つの読者層、
三つの言語です。

## 翻訳が自分のデータモデルに教えてくれたこと

会社名は事実だと思っていました。しかし、`freee K.K.`、`freee株式会社`、`freee 주식회사` は
同じ会社であり、日本語ページではそのうち一つが別の一つのすぐ上に直接表示されていました。

所在地の行は、同じ点をもっとはっきり示しました。私はこれを
`{location} — from {origin}` として作っていましたが、そこには英語の語順が静かに埋め込まれて
います。韓国語ではマーカーが最後に来ます（`대구 출신`）。日本語も同じです（`韓国・大邱出身`）。
独立して作業した二人の翻訳者が、どちらもコードを変える代わりに表現を曲げていました。
別々の方向から二人が同じ壁に当たるなら、その壁がバグです。
