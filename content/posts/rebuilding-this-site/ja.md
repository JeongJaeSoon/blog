以前のサイトには、購入したポートフォリオテーマをそのまま使っていました。見た目は
悪くない。でも各ページは Bootstrap、Font Awesome、Isotope、Magnific Popup、
smooth-scrollbar、anime.js、スライダーライブラリまで抱えていました。コンテンツの
読み込み処理も、`fs.readdirSync` を使う同じ四十行が分類ごとに八回コピペされていました。

しかもデモの作者名は Artur Carter のまま。自分のサイトとは言いにくい状態でした。

## 現在の構成

- App Router と静的レンダリングを使う **Next.js 16**
- **React 19** と **TypeScript**
- JavaScript の設定ファイルではなく CSS で設定した **Tailwind CSS v4**
- シンタックスハイライトに **Shiki** を使う **unified / remark / rehype**

UIフレームワークもコンポーネントライブラリも、既製テーマも使っていません。依存関係が
一画面で読める量に収まった。それだけでも作り直した意味がありました。

## コンテンツの置き場所

見る場所は三つだけです。

```text
content/profile.ts      → 事実: 日付、URL、リポジトリ、技術スタック
content/i18n/{en,ko,ja} → 翻訳が必要なすべての文字列
content/posts/<slug>/{en,ko,ja}.md → ブログ
```

肝は最初の二つを分けたことです。入社日、リポジトリ名、プロジェクトで使う言語などの
事実は **一度だけ** 保存し、翻訳するのは文章だけ。`2023-11` を三か所に置けば、いつか
どれか一つだけ更新し忘れます。

両方とも型付けされているので、開始日がない職歴やキーが欠けたロケールを追加すると、
空の span を描画するのではなくビルドが失敗します。投稿は frontmatter を持つ Markdown
ファイルです。

```yaml
---
title: A post
date: '2026-08-30'
summary: One or two sentences.
tags: [nextjs]
lang: en
draft: true
---
```

ブログは一記事一ディレクトリです。中に英語、韓国語、日本語の Markdown を置き、
ディレクトリ名を共通の URL スラッグにします。`lang` とファイル名が違う、あるいは
翻訳が一つ足りない場合はビルドを止めます。言語ボタンを押して 404 になるよりましです。

`draft: true` にすると、投稿は `next dev` と Vercel の preview デプロイでは見えますが、
本番ビルド、RSSフィード、サイトマップからは外れます。下書きを実物で読む場所が preview です。

## 履歴書としての部分

ホームページ自体が履歴書です。同じ型付きデータを読み、きれいに印刷されます。`Cmd+P` を
押すとナビゲーション、フッター、「すべてのリポジトリ」へのリンクを外し、連絡先の
ハンドルを展開するので、紙の版にも連絡先が残ります。一つの情報源、二つの読者層、
三つの言語です。

## 翻訳が自分のデータモデルに教えてくれたこと

会社名は事実データだと思っていました。ところが `freee K.K.`、`freee株式会社`、
`freee 주식회사` は同じ会社でも、表示する言語によって名前が変わります。日本語ページでは、
その二つが上下に並んでしまいました。

所在地の行ではもっと露骨でした。`{location} — from {origin}` という組み立て自体が
英語の語順です。韓国語は `대구 출신`、日本語は `韓国・大邱出身` と後ろに「出身」が来る。
別々に作業した二人の翻訳者が、どちらもコードに合わせて文章を曲げていました。二人が
同じ場所で困るなら、翻訳ではなくデータモデルのほうを直すべきです。
